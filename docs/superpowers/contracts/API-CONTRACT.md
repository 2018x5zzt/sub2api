# API Contract

- Scope: P0 external HTTP contract for `origin/test/xlabapi` backend routes. This document is a guardrail for frontend-v2 rewrite and backend refactor: method/path, request fields, response envelope/schema meaning, and side effects must remain compatible.
- Source of truth: `origin/test/xlabapi` backend route registration and handler code only. Current working tree and `main` are not used as API truth.
- Envelope invariant for `/api/v1/*` JSON APIs: success is `HTTP 200` with `{ "code": 0, "message": "success", "data": ... }`; paginated success is `data.items`, `data.total`, `data.page`, `data.page_size`, `data.pages`; errors keep `{ "code", "message", "reason?", "metadata?" }`. Evidence: `origin/test/xlabapi:backend/internal/pkg/response/response.go:14`, `origin/test/xlabapi:backend/internal/pkg/response/response.go:32`, `origin/test/xlabapi:backend/internal/pkg/response/response.go:123`.
- Compatibility rule: new optional response fields are allowed; removing fields, changing field type, changing null-vs-empty semantics, changing path/method, or changing business meaning is a contract break.
- Authentication shorthand: `JWT` means the route is under `jwtAuth`; `Admin` means `adminAuth`; public means no JWT/Admin middleware on that route.
- Open items are marked `[待确认]` when handler behavior is not fully knowable from the P0 read pass.

### Stable Notes

- `POST /api/v1/auth/validate-invitation-code` is registration-invitation validation, not user affiliate invite validation. It validates `redeem_codes.type=invitation` and returns `data.valid` plus optional `data.error_code`. Evidence: `origin/test/xlabapi:backend/internal/server/routes/auth.go:54`, `origin/test/xlabapi:backend/internal/handler/auth_handler.go:509`.
- Login/register/refresh token field names are snake_case and must remain stable: `access_token`, `refresh_token`, `expires_in`, `token_type`, `user`.
- OAuth callback routes are P0, but exact redirect/cookie variants need focused golden capture; do not normalize them into generic JSON.

## 5. subscriptions

### Dual-Track Boundary

- Old group subscription track: user owns subscriptions to a single group. Primary user endpoints are `/api/v1/subscriptions*`; core response DTO is `UserSubscription` with `group_id`, `starts_at`, `expires_at`, `status`, per-window starts and usage, optional `group`.
- New product subscription track: user owns subscriptions to a product that binds one or more groups. Primary user endpoints are `/api/v1/subscription-products*`; core response DTO is `ActiveSubscriptionProduct`/`SubscriptionProductSummary` with `product_id`, `subscription_id`, product `code/name`, shared product usage/limits, carryover fields, and `groups[]` including `debit_multiplier`.
- Fields with aligned semantics across both tracks: `status` means subscription lifecycle state; `expires_at` means entitlement expiry; `daily_usage_usd`, `weekly_usage_usd`, `monthly_usage_usd` mean consumed quota in the relevant rolling/fixed window; daily/weekly/monthly limit fields are USD quota caps; `daily_window_start`, `weekly_window_start`, `monthly_window_start` are reset-window anchors when present.
- Fields with different semantics: old `group_id` means the entitlement target group itself; product `groups[].group_id` means a group bound to the product quota pool. Old usage is single-group subscription usage; product usage is shared product quota pool usage and can debit different groups by `groups[].debit_multiplier`.

### Stable Notes

- Admin list endpoints mostly use the shared pagination envelope; endpoints returning raw conflict (`admin/accounts` mixed-channel 409) or `304` ETag are intentional exceptions and should be pinned separately.
- Admin user/group/account DTOs include sensitive/internal fields that normal user endpoints must not expose. Contract tests should cover both positive admin fields and negative user-side leakage.
- For admin settings, field-level completeness is intentionally not exhausted here; P0 contract must at least pin response envelope, a representative set of high-risk fields, and nil/empty update semantics.
